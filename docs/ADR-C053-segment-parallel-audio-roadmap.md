# ADR-C053：GOP 分段并行与音轨共存路线（决策）

日期：2026-09-20 · 状态：**已采纳（决策定稿；实现另立计划）**
关联：ADR-C050（GOP 分段并行——本 ADR 修订其"音频互斥"边界）、
ADR-C051（v1.1 音频轨）、ADR-C052（v1.4 elst）、
`topos_container_audio_optimization_plan_2026-09-20.md` §3 M-B5

## 1. 背景

ADR-C050 的分段并行实现将音轨显式拒之门外（`add_audio_stream` 在
`_gop_seg` 模式抛 RuntimeError）：每段独立 mux，音频样本无处安放。用户
在开启 V9 分段（4K 显式 opt-in / ≤2K 默认开）时若同时勾选音频，导出直接
失败——两条能力互斥，且失败发生在编码启动期（用户已配置完导出参数）。

## 2. 方案对比（plan M-B5 任务 1）

| 方案 | 思路 | 工作量 | 通用价值 | 风险 |
|---|---|---|---|---|
| **A：native 追加轨工具** | 读已 finish 文件的 moov，追加音频 trak + 音频 mdat 分片 + 重写 moov（自产布局已知，可行性高） | 2-3 天（moov 解析已有；追加+重写+co64 分档是新代码） | 高——任何"后配音频"场景复用（外部工具合入、二次封装） | faststart 语义破坏面（co64/偏移重定位）需专门小节 |
| **B：段外独立 pass** | 分段并行只管视频；音频渲染/编码独立完成后走 A 的追加工具合并（B 依赖 A 的核心件） | A 的 2-3 天 + 编排 0.5-1 天 | 中——导出期不占额外峰值内存 | 音频与视频时长对齐由编排层负责（测试面） |
| **C：维持互斥 + 文档化** | 现状；preflight 提前到 UI 配置期报错 | 0（已有启动期 fail-fast） | 无 | 用户二选一，能力缺口保留 |

## 3. 决定

**采纳 B（段外独立 pass + A 的核心件），实现另立计划**（默认不在本期
M-B 系列内实施）。要点：

1. **核心件 = A 的"moov 重写 + 追加轨"native 工具**（`tc_movie_append_
   audio_track` 族）：读已 finish 文件 → 追加音频 trak（stsd/elst 全语义
   复用 v1.4 写侧）→ 音频 chunk 追加进 mdat → 重写 moov。faststart 兼容
   小节专门处理：追加后布局选择（标准/重排 faststart）与 co64 升级规则
   沿用 `tc_movie_faststart` 的既有逻辑。
2. **导出编排**：分段并行模式下，音频母带渲染与（如需）AAC 编码独立
   pass 完成，导出收尾时调追加工具合并——视频段并行吞吐不受影响，
   音频不占分段峰值内存。
3. **过渡期（本 ADR 生效至实现落地）**：维持 C 的启动期 fail-fast，
   但把错误信息改为指向本 ADR 的决策（"分段并行 + 音频将于后续版本
   支持，可关闭 V9 分段或关闭音频"）——preflight 同步提示，避免用户在
   编码启动期才发现冲突。
4. **实现计划的验收锚点**（防走样）：追加产物必须通过
   `golden_mov_audio` 全部用例的字节形态校验（elst/wave/V2 语义与
   v1.4 一致）；ffprobe/AVFoundation 双轨识别；分段并行吞吐不回退
   （ADR-C050 §5 基准复测）。

## 4. 后果

- 分段并行与音频的互斥是**临时边界**而非产品决策；preflight 文案按
  D3 调整（后续小提交）。
- 实现工作量（A 核心件 2-3 天 + 编排 0.5-1 天）另立计划立项；
  本 ADR 只冻结路线与验收锚点。
- ADR-C050 的"音频显式拒绝"条目由本 ADR 修订：拒绝语义保留至实现
  落地，落地后删除。
