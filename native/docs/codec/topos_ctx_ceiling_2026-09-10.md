# rANS order-1 上下文建模天花板测量（2026-09-10，含两次勘误）

**结论（勘误后）**：真实素材全 qp 段，单因果上下文的净收益为
**+1.2~2.7% payload**（qp20-44 lvl|位置桶，qp56+ 前 lvl/前块 DC 桶）。
V7-R2（ADR-C036）实现拿满该天花板（实测 −1.2~−2.8%，解码 ~1×）。
**初版报告声称的 +24~29% 是测量工具两处 bug 的产物**——详见 §6 勘误，
保留完整记录以固定方法论教训。

## 1. 背景与动机

ADR-C035 把产品默认熵翻到 rANS（per-slice order-0）后，测量"若引入
现代编码器标配的上下文建模（CAVLC/CABAC 自 H.264 起），天花板多少"。
零位流成本——只加 dev 捕获钩子，不改任何编码输出。

## 2. 方法

### 2.1 捕获钩子（native 侧）

`src/codec/ctx_ceiling.{h,c}`（dev-only，默认关）：在两条生产量化/
token 遍内按**解码序因果上下文**累积条件联合直方图，每 slice 以理想
（未量化）模型计算符号位数并折叠进全局累加器：

- a0(族) = Σ_slice [N·log₂N − Σ m·log₂m]（per-slice order-0 理想熵）；
- a1(模型) = Σ_slice Σ_ctx [N_c·log₂N_c − Σ c·log₂c]；
- adaptive(族) = Σ_slice min(a0, 最优 a1 − 2bit 信令)。

模型域（上下文全部为解码端零成本因果状态）：

| 模型 | 上下文 | ctx 数 |
|------|--------|-------|
| R1 | run \| 前一系数扫描位置桶 | 8 |
| R2 | run \| 前一对 run 桶 | 7 |
| R3 | run \| 本块 DC 类桶 | 4 |
| L1 | lvl \| 同对 run 桶 | 6 |
| L2 | lvl \| 前一对 lvl 类桶 | 5 |
| L3 | lvl \| run×前 lvl 桶 | 30 |
| L4 | lvl \| 本系数扫描位置桶 | 4 |
| D1 | dc \| 前块 DC 类桶 | 5 |

符号轴为完整类别（DC 29 / RUN 64 含 EOB / LEVEL 28）。
log₂ 为自实现 atanh 级数（|err|<1.5e-6，不引 libm）。

### 2.2 表开销 allowance

条件模型每 slice (C−1)×|族| 额外字节（8-bit/symbol 粒度），net8 已扣。

### 2.3 工具与语料

```
TOPOS_CODEC_LIB=build/release/topos_codec.dylib \
  python3 tools/bench_ctx_ceiling.py --frames 8 --qps 20 32 44 56 68 76
```

语料：/tmp/p5m/src1440.raw、src720.raw、2K_prores422HQ.mov。
原始数据 `tools/ctx_ceiling_2026-09-10.json`（勘误版重跑）。

## 3. 勘误后结果（real_1440p_raw，8 帧；net = 扣 8-bit 表开销后占 payload %）

| qp | 符号位理想 a0 | 最优模型 | net8 |
|----|------------|---------|------|
| 20 | 175.5 Mbit | L4（lvl\|位置） | +1.21% |
| 32 | 174.9 Mbit | L4 | +1.57% |
| 44 | 167.6 Mbit | L4 | +2.11% |
| 56 | 106.4 Mbit | L2（lvl\|前 lvl） | +2.66% |
| 68 | 21.5 Mbit | L2 | +1.11% |
| 76 | 6.9 Mbit | D1（dc\|前块） | +0.66% |

720p / 2K prores 语料同形（±1pp）。run 族全 qp 段 ≤0.3%（不做）；
L3 组合无增益（信息一维）。

## 4. 结论

1. lvl 族单因果上下文（位置或前 lvl）净省 **1.2~2.7% payload**，
   qp56 达峰后随符号预算萎缩而衰减；高 qp 段 DC 族（前块类）接棒
   但绝对量小。
2. 与文献口径一致（H.264 时代上下文增益 2-5% 量级）——我们的
   per-slice 两遍静态表已把 order-0 的确定性结构吃干净，剩余可拿的
   是位置/邻块相关性这一块。
3. 组合上下文（30-ctx）无增量：信息本质一维（位置→幅度衰减）。
4. 锚点验证：shipped 符号位 ≈ per-slice order-0 理想熵 + 1.1~2.8%
   （全 qp 段）——rANS 实现无欠账，上述差值即真实可拿空间。

## 5. 正确性保障

- `tests/unit/test_ctx_ceiling.c`：log2 精度（8 已知值）；符号计数与
  sym_hist 钩子逐族相等；slice 数与 stats 一致；条件熵不等式
  a1 ≤ a0（8 模型，勘误后为非空洞断言）；pooled 联合总数；单线程
  确定性；默认关零副作用。
- V7-R2 实现（`bitstream_spec_v7r2_ctx.md`）与天花板对拍：qp20-84
  实测 −1.2~−2.8%，覆盖勘误后天花板的全部区间。

## 6. 勘误记录（方法论教训）

初版报告（同日早版）曾声称 +24~29% payload 并据此发起 ADR-C036。
实现后 A/B 仅 −1.4~−2.3%，回溯定位出测量工具两处 bug：

1. **L 族符号轴粗类化**：joints 索引用 `lvlcat_b(cat)`（4 桶粗类）
   而非完整 cat（0..27）——测得的是"粗类字母表"的条件熵（上限
   2 bit/符号），而非真符号条件熵。差一个量级。单测的 a1 ≤ a0
   不等式因此空洞成立（4 类熵 ≤ 28 类熵恒真），未能拦截。
   *教训：条件熵不等式对"符号轴被粗化"的测量不设防——符号轴定义
   必须与被替换的生产模型逐类别一致，并加"联合边际 = 生产直方图"
   这类强一致断言。*
2. **D1 上下文非因果**：`tc_ctx_dc` 用本块自身 DC 类做上下文
   （对角 joint，H(X|f(X)) 天然极小），高 qp 段虚标（qp76 曾报
   +12.7%，勘误后 +0.66%）。编码器实现照抄了该 bug 到 collect
   （表与流错配，还引出一次 roundtrip 失败排查），后向游走与
   解码器始终是正确的前块条件。
   *教训：上下文因果性无法用熵数值自检——必须从解码器视角写上下文
   定义（"解码到该符号时什么已知"），并让测量与实现的桶函数共享
   同一 inline（勘误后 rans.h `tc_rans2_*_ctx` 为唯一真相源）。*

两处修正后重测如 §3；JSON 已覆盖为勘误版。
