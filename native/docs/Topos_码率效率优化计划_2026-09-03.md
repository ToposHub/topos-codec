# Topos 码率效率优化计划（RD 效率战役，2026-09-03）

**目标一句话**：在画质不降、编码/解码速度不回退的前提下，把各档位码流体积尽可能做小；
444 家族与 ProRes 的同码率质量差距收敛到 ≤2 dB。

**总纲门（G1–G4，适用于全部阶段）**：

| 门 | 判据 |
|----|------|
| G1 画质 | 同 qp 下 PSNR/SSIM 不降；结构变更需 RD 净提升；档位交付质量 ≥ 基线锚点 |
| G2 体积 | P4 完成口径：同画质锚点体积 ↓≥20%；444 对 ProRes 差距 ≤2 dB |
| G3 速度 | 编码（core/E2E）与解码（p50/p95）相对 V1 基线回退 ≤3%（全 qp×分辨率矩阵） |
| G4 兼容 | 解码器优化不得改变 V2 输出（bit-exact）；编码端变更需全量回归 + 多代漂移复测 |

---

## §0 背景与数据基线（全部实测，2026-09-03）

### 0.1 与 ProRes 的同码率对拍（素材：2K/4K_prores422HQ + 4K_prores4444 家族）

- 422 家族：topos 各档在其实测码率处，比 ProRes 率失真线低
  **−1.81 ~ −3.86 dB**（Y-PSNR，2K/4K）；
- 444 家族：topos 4444 同码率低 **−5.75 ~ −6.04 dB**（2K：305 vs 290 Mbps，50.74 vs
  56.78 dB；4K：1172 vs 1150 Mbps，55.84 vs 61.59 dB）——超出熵编码增益能解释的范围，
  444 路径存在结构性问题（P2 专项）；
- 档位名义码率按 Apple 标称表定标并实测命中（10/12 组合 0.93–1.04）；例外：
  proxy@4K 实测 +69%（qp=63 天花板压不进目标）、extreme@2K +23%。

### 0.2 熵编码 V2 VLC vs V1 Rice（`bench_out/6b3dfe9d/…/rd_result.json`）

| 指标 | 2K | 4K |
|------|----|----|
| 同 qp 同 PSNR 码率节省 | 27–32% | 23–27% |
| V2 解码 p50 相对 V1 | +2% ~ +18% | **+14% ~ +52%**（低 qp 端最重） |
| V2 编码相对 V1 | ≈持平 | **+4% ~ +36%**（低 qp 端最重） |

V2 已实现、质量与 V1 逐点相等（同 qp 同 PSNR）；未转正默认的唯一原因是速度门
（P2-02 决策 §110）。

### 0.3 代码现状（优化对象的事实）

- 解码快路：12-bit 一级表 + 8-bit 二级表 + 64-bit cache 窗口
  （`entropy/vlc.h` `tc_vlc_decode_cat`），设计已经 table-driven；
- **瓶颈假设**：三族 book 工作集 ~240 KB（primary 16 KB + secondary ≤64 KB/本），
  超出 L1 → 每符号 1–2 次依赖性内存加载；Rice 每符号 ~10 ops 纯运算、无查表；
- 编码端：V2 多一次 token 遍（三族 histogram）+ 4 本精确位计数选表
  （`codec.c` vlc_best_book，已是直方图法）；Rice 无此遍 → 4K 编码回归来源；
- 位 IO：128-bit reservoir writer / 64-bit cache reader，均已优化。

### 0.4 结论：体积优化的主杠杆排序

1. **P1 V2 提速转正**（~25–30% 熵增益落袋，画质零损失）——P4 的前提；
2. **P2 444 结构性修复**（该家族 ~6 dB 中超出熵可解释的部分）；
3. **P3 量化死区微调**（编码侧近零成本 RD 增益）；
4. **P4 档位重定标**（质量钉扎下调 target_bpp，把收益兑换成体积）。

## §2 P1 VLC 编解码提速至 V1 水平 → V2 转正默认（核心战役）

### 任务

- **T1.1 profiling**：xctrace Time Profiler / `sample` 对 4K V2 解码+编码定量热点；
  产出「每符号成本分解」表（L1/L2 命中、分支占比、refill 占比），后续优化以此排序；
- **T1.2 解码表瘦身**：primary 表 u32→u16（kind 字段在单族查询点冗余可去；
  secondary 行基址挪到 ≤64 项侧表）→ 每 book ~80 KB → ~20 KB，三本 ~60 KB；
  更新 `tc_vlc_book_build` 填表与单测钉值；
- **T1.3 解码微架构**：下一符号表项软件 prefetch；分支裁剪与重排（热路优先、
  m_max 校验融合）；核对 refill 频率（窗口消耗模式）；
- **T1.4 编码端**：确认 token/histogram 遍与 quant→token 生成遍的融合状态；
  histogram bucket 向量化（clz→bucket 直映射）；book 选择**必须保持精确最小位
  数 + 同分最小 id 语义不变**（码流 bit-exact 不变）；
- **T1.5 转正**：产品编码器默认 entropy_mode=V2（V1 保留显式可配）；capability /
  spec 文档更新；坏包隔离与 fuzz 用例补 V2 矩阵（截断/翻转/前缀冲突 × 三族）。

### 验收门

- bit-exact：优化前后 V2 解码输出逐位一致（随机流 + 真实码流 × 截断位置矩阵）；
  编码端优化后码流与优化前逐位一致；
- 速度：V2 解码 p50/p95 ≤ V1×1.03，V2 编码 ≤ V1×1.05（全 qp×分辨率矩阵，同机）；
- 质量：V2 转正后全档 RD 与 V1 逐点持平（P2-02 已证，回归确认即可）；
- 证据：profile 热点表、速度矩阵 JSON、单测绿。

### 风险与回退

若解码无法达 ≤1.03×：V2 不转默认，退守「低码率场景可选档」；P4 改为在 V1 下按
P2/P3 收益重定档（体积收益相应缩水，如实记录）。
跨平台 bit-exact（Windows/ARM64 真机）维持 P2-02 列为**发布前**开放前置项，不在
本战役门内（无硬件，P2-06/P2-09 跟踪）。

## §3 P2 444 模式 RD 专项（结构性 −6 dB）

- **T2.1 诊断**：同内容固定 qp 阶梯分解——Y/U/V 分平面 RD 与字节占比；
  444 量化路径核查（qmatrix 在 444 的应用、色度平面预算、profile 5/6 差异）；
  与 ProRes 4444 同点对照；
- **T2.2 修复**（按诊断结论；候选：444 亮度/色度 qp 分配、平面字节预算、
  矩阵缩放；禁止引入需新 ABI 的方案——那是 P1-05 V2.1 的地盘）；
- **T2.3 验收门**：444 同码率 RD 提升 ≥3 dB 或对 ProRes 差距 ≤2 dB；
  422 路径不动（bit-exact）或 RD 不降；速度 Δ≤3%；多代漂移复测。

## §4 P3 量化 RD 微调（编码侧近零成本）

- **T3.1** 死区/量化偏移网格扫描（离线，选参固化为 qp 曲线，不进运行时搜索）；
- **T3.2 验收门**：RD +≥0.3 dB@同码率（2K/4K × 422/444）；编码 Δ≤+2%；
  解码零影响（码流格式不变，量化值分布变化）；多代漂移复测；
- 说明：码流会变化（量化值不同），同版本解码器可解；需 bump 编码器内部版本注记。

## §5 P4 档位码率重定标（质量钉扎）

- **T4.1** 在 P1–P3 完成后的新 RD 曲线上，六档逐一取「旧档位交付质量锚点」，
  下调 `target_bpp` 至质量持平（预期 −20~−35%；444 家族叠加 P2 收益）；
- **T4.2** proxy@4K qp63 天花板：新目标下复测命中率；受 63 上限物理约束的部分
  如实记录（不虚标）；
- **T4.3** 更新 `topos_profiles.py`（reference 区间换算、文档）+ capability manifest；
- **验收门**：全档命中率 ≥0.95；新档位质量 ≥ 旧档位锚点（逐档 PSNR 锚定）；
  速度门同 G3；全量回归绿。

## §6 P5 总验收

- 全量回归：A3 速度矩阵、round2 A/B/C、RD vs ProRes 终榜、多代漂移、坏包矩阵；

### 战役净结论（2026-09-03 执行 / 2026-09-04 P1.5+P4+AQ 落地）

1. **已落地（第一轮，2026-09-03）**：VLC 编码提速至与 Rice 持平（原 +4~36%）；
   VLC 解码 1.33x→1.17x；444 档色度 qp 偏移 +4。全部 bit-exact。
2. **已落地（第二轮，2026-09-04，用户批准 V2 转正）**：
   - V2 canonical VLC 成为产品默认（c0f7068d）；
   - P4 质量钉扎重定标（822c22f4/94b31cc8）：**六档体积 −26.4~−32.9%，画质逐点持平**；
   - V2.x AQ 修正落地（64e7e219，默认关）：c14abbce 的"+0.37~+0.48 dB"经复跑
     对账为**打印符号误读**（全平面掩蔽方向实际 −0.37~−0.48 dB）；修正固定
     qp 路径静默失效 bug + 重定向色度专属后，同码率 2K422 +0.19~+0.23 dB、
     444 家族 ≈0；质量钉扎 bpp 空间全 12 格 **0~1.6%**——不足以调档，bpp 与
     默认开关均维持现状。
3. **对照 ProRes 的差距现状**：422 家族同画质码率倍数从 ~1.4-1.9× 降到
   **~0.9-1.3×**（proxy@2K 已贴住 ProRes 插值线，hq 仍 ~1.3×）；444 家族
   仍 ~1.8×+（结构性——AQ 的 slice 粒度实测只能吃到边缘收益；**逐系数
   RDO（01a7466d）落地后 444 同 bpp luma +0.4~0.6 dB**，但受 qp 网格粒度
   限制无法兑换成 bpp——剩余差距需更细的 qp 域或矩阵工程）。
4. **后续**：RDO 默认开拍板（luma↔chroma 交换比：μ=50% 中档 +0.4~0.6Y/
   −1~3UV @同 bpp，或 μ=100% 激进档 +0.9~1.9Y/−5UV@12bit）；RDO 深化
   （DC 精修 / ±2 候选 / 逐系数 trellis）；qp>63 上限扩展（顶格档地板：
   proxy 全分辨率、extreme@2K、pro444@2K 77% 帧）；跨平台 bit-exact 验证
   仍是 V2 默认的发布前置。
