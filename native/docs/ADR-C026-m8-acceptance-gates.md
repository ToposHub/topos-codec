# ADR-C026 — M8 V1 总验收：正式 Go/No-Go 门冻结与判定（启动 M9）

- 日期：2026-08-31
- 状态：已接受（M8 交付）
- 关联：`Topos_编解码性能超越_ProRes_DNxHR_优化计划_2026-08-31.md` §13/§14/§16；
  `bench_m8_acceptance_2026-08-31.md`（实测记录）；ADR-C022（R6 门槛 v2）；
  benchmark_protocol.md §4/§5

## 0. 背景与问题

计划 §13.1 的 ProRes/DNxHR 门为「临时参考门」，明确要求 M0 从同源、同码率、
同线程的新测试得到顺序 avg/p95 与随机 avg/p95 四项完整分布后，在 ADR 中
冻结正式 Go/No-Go 门。M0–M7 期间仅有 Topos 单侧数据与计划起点基线；M8
补齐了公平对照矩阵（同源真实素材、8 线程、±5% 码率锚点、产品路径），本
ADR 据此冻结正式门并给出 M8 行的 Go/No-Go 判定。

## 1. 冻结的正式门（2026-08-31 基准机口径）

正式门 = 在协议冻结基准机（i9-9900K/8C/32GB/macOS 15.3.1）、真实素材、
产品路径、warm、同线程（8）、同码率（±5%）下的判定。「超过」沿计划 §13.1：
3 个进程 median 均快 ≥5% 且 95% CI 不跨 0。

| 门 | 1080p | 4K | 依据 |
| --- | ---: | ---:| --- |
| G1 顺序解码 avg | ≤5 ms | ≤18 ms | V1-kernel 里程碑（M2–M5 达成线） |
| G2 随机解码 p95 | ≤7 ms | ≤23 ms | 同上 |
| G3 顺序解码超 ProRes | <1.57 ms | <8.81 ms | 本机 prores422HQ PyAV 实测（3 进程 median 口径沿用） |
| G4 随机解码超 ProRes | <18.20 ms(p95) | <78.47 ms(p95) | 同上 |
| G5 同码率编码 avg | 追平较快对照（DNxHR 7.3/30.8 ms） | 同左 | §13.2「追平较快的对照」 |
| G6 同码率质量 | Y-PSNR 差 ≤1dB 或经质量决策接受 | 同左 | §16「无不可接受倒退」 |

## 2. M8 实测判定

| 门 | 1080p | 4K | 判定 |
| --- | ---:| ---:| ---|
| G1 | 4.02 ms | 14.50 ms | ✅ |
| G2 | 5.19 ms | 15.80 ms | ✅ |
| G3 | 4.02 vs 1.57 | 14.50 vs 8.81 | ❌（差 1.65–2.56×） |
| G4 | 5.19 vs 18.20 | 15.80 vs 78.47 | ✅（2.7–5.0× 优） |
| G5 | 33.5 vs DNxHR 7.3 | 82.8 vs 30.8 | ◐（过 prores_ks 1.60–2.91×，未过 DNxHR） |
| G6 | −4.4 dB vs ProRes | −5.2 dB vs ProRes | ❌ |

**判定：达 V1-kernel（G1+G2）但未达 ProRes 正式门（G3/G6 未过）→ 按计划
§14 决策树启动 M9（V2 schema + canonical VLC），不触发 No-Go 复盘。**

## 3. 决策

1. **M9 立即启动**，前置为 §12.0 V2 schema reconciliation ADR（与 Micro-GOP
   计划协调 major=2 字段，不允许单侧抢占）。G3 的分解靶子 = 熵解码 CPU
   （4K ~55ms/帧，M5 阶段画像第一热点）；G6 的分解靶子 = Rice 后缀冗余 +
   固定 qmatrix 率失真（qp57 近满量程档位粒度过粗）。
2. **V1 冻结维持**：M8 期间发现的 binding 每帧 199MB 输出缓冲分配已在
   `41f0bf0d` 修复（产品路径编码 1080p 84.7→34.5ms，逐字节差分 0 不匹配），
   不涉位流变更；golden 全绿不受影响。
3. **优势区间入宣传口径**：随机访问（2.7–5.1×）、解码内存（1/2.1–1/5.3）、
   多代稳定（10 代 −0.4~−0.5dB vs ProRes −7.7~−8.0dB）可在对外材料声明，
   措辞为「区间优势」；顺序解码与同码率质量不得声称追平/超过（§16）。
4. **sized 语义偏差登记**：encode_sized 实际码率低于目标 18–21%（legacy
   「首个不超过」阶梯语义 + 帧间复杂度波动）。parity 优先不改 V1；V2 码控
   重设计列入 M10 候选。
5. **流程修正**：性能相关提交必须同步重建 build/release 并在报告中记录
   dylib commit（M8 曾因 release 陈旧差点把旧库数据入库）。

## 4. 后果

- M9 Go/No-Go 沿用本 ADR 门（G3/G5/G6 为 M9/M10 出口条件；G1/G2 作为
  回归下限不得倒退）。
- G6 的「≤1dB 或质量决策接受」留给 V2 VLC + 率失真量化验证；若 V2 后仍
  >1dB，升级为产品决策（档位重定位/码率惩罚声明）。
- 跨平台 runner（Intel/ARM64/Win x86_64）与 TSan 全绿为 §16 发布级条件，
  由 M10/M11 承接，不阻塞 M9 开工。
